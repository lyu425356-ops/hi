Codex 与 Claude Code
环境目录全景对照

全局 vs 项目级 · 配置与技能落位 · 会话存储机制 · 双环境迁移 · API Key 与中转站原理

本文对比两个 AI 编码助手在文件系统上的组织方式。核心差异：Claude Code 以单一目录收纳全部内容；Codex 将技能、配置、项目指令分散在三处，其中多个路径名由程序内部写死，不可重命名。示例中的 <user>、<project> 均为占位符。

一、目录全景对照图

左侧 Claude Code 一个目录管全部；右侧 Codex 原生分成三处。虚线表示同一层级的等价关系。

二、会话存储机制差异

根本分歧：Claude Code 按项目路径分目录物理隔离；Codex 扁平按日期存放，靠文件内 cwd 字段区分归属。

三、Codex 原生锁定路径清单

以下路径名由 Codex 程序内部的发现逻辑写死，重命名后对应功能即失效。这是「为什么 Codex 非得分成几处」的根本原因。

路径层级用途约束
$CODEX_HOME/skills全局全局技能加载目录原生锁定 默认 ~/.codex/skills
.agents/skills项目项目级技能原生锁定 改名后技能不被发现
.agents/plugins项目项目级插件原生锁定
.codex/config.toml项目项目配置、环境变量注入原生锁定
.codex/agents项目Agent 定义（TOML 格式）原生锁定
.codex/hooks项目钩子脚本原生锁定
AGENTS.md项目根项目指令文档（project doc）原生锁定 必须位于项目根
.codex/skills项目指向 .agents/skills 的软链可选自建 纯视图，可随时删除

四、双环境迁移指南

哪些能直接搬、哪些必须手工转写、哪些不该搬。

内容可迁移性操作要点
skills/ 直接复制 目录结构与 SKILL.md 格式两边完全兼容，rsync -a --exclude='.git' --exclude='.DS_Store' 即可。唯一必查项：SKILL.md 正文里嵌的脚本路径前缀，迁移后需对齐到目标环境，否则照文档执行会报文件不存在。用 grep -rn 'claude/skills\|agents/skills' SKILL.md 核对。
agents/ 手工转写 格式不同：Claude Code 用 Markdown（agents/*.md），Codex 用 TOML（.codex/agents/*.toml）且指令正文需放进 developer_instructions 字段。无自动转换工具。
配置文件 不要迁移 语义不对等。Claude Code 的 settings.json 核心是权限白名单（可访问域名、可执行命令模式）；Codex 用 config.toml 的 sandbox_mode + approval_policy 表达同类语义，粒度完全不同，逐条搬运既无处可放也无意义。
MCP 配置 格式转写 Claude Code 用 .mcp.json 的 mcpServers 字段；Codex 写在 config.toml 的 [mcp_servers.<name>] 表下。字段含义（command/args/url）基本一致，结构需改写。
指令文档 改名即可 CLAUDE.md ↔ AGENTS.md，Markdown 内容通用。注意落位差异：Claude Code 收在 .claude/ 内，Codex 项目级必须放项目根。
会话历史 不可迁移 存储布局与 jsonl 内部结构均不同（按项目分目录 vs 按日期扁平 + cwd 字段），无现成转换工具。

五、API Key 与中转站原理

为什么填一个 Key 就能立刻用上模型？为什么模型列表里会出现厂商官网查不到的名字？两个问题的答案在同一条链路上。

六、速查卡

找全局技能

  • Codex → $CODEX_HOME/skills/
  • Claude → ~/.claude/skills/
  • 两者均为单一目录

找项目技能

  • Codex → <project>/.agents/skills/
  • Claude → <project>/.claude/skills/
  • Codex 可加软链统一入口

找会话记录

  • Codex → sessions/ 按日期
  • Claude → projects/ 按项目
  • Codex 检索用 codex resume

装新技能落哪

  • 通用 → 全局 skills/
  • 仅本项目 → 项目 skills/
  • 两边都要用则各放一份
三个容易踩的坑

1 · 技能文档里的硬编码路径。SKILL.md 正文常嵌有可执行命令，路径前缀写死了源环境（如 .claude/skills/...）。跨环境复制技能目录后必须同步改写这些前缀，否则按文档执行会报文件不存在。

2 · 全局家目录可能不止一个。Codex 的全局目录由 $CODEX_HOME 决定，不同发行版或安装方式可能指向不同路径。若历史上装过多个版本，家目录下会残留多个配置目录，判断当前生效的那个应以 $CODEX_HOME 为准，而非目录名。

3 · 项目配置里的明文凭据。.codex/config.toml 可通过 [shell_environment_policy.set] 注入环境变量，常被用来放 API Key。这类文件若随仓库提交会泄露凭据，应确认已被 .gitignore 排除。
